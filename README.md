# AutoFishing New

Windows Minecraft 自动钓鱼工具。新版保存在 `AutoFishing - New`，原版目录不受影响。

## 启动

双击 `Run.bat`，启动器检查 Python 和依赖；缺少依赖时会尝试安装。也可在本目录运行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

需要 Windows 10/11、64 位 Python 3.10+。本机验证环境为 Python 3.14.6。首次加载 RapidOCR 可能需要下载模型；加载在后台完成，OCR 就绪前不会开始钓鱼。无需先开 Minecraft 即可打开设置界面。

## 首次设置

1. 进入 Minecraft 世界，点击“刷新游戏窗口”。推荐窗口或无边框模式。
2. 停止自动钓鱼，按 F8 或点击“选择 Title 区域”，紧贴游戏中央“咬钩！”或“上钩！”标题框选单行范围，并留少量边距。避开聊天、计分板和物品栏。
3. 用“测试 Title”检测 12 秒，并切回游戏，检查识别文字、置信度和预览。此测试不会点击鼠标。
4. 在“识别与设置”中选择当前实例的 `logs/latest.log`，点击“保存设置”。自动查找仅覆盖常见 `.minecraft` 目录；第三方启动器的独立实例通常需要手动选择。
5. 默认先手动抛竿，再按 F6 开始。也可开启“开始时自动抛竿”，然后保存。

ROI 保存为游戏客户区的比例，随窗口移动和分辨率缩放重新计算。更换资源包、GUI 缩放或标题布局后请重新框选。开始时必须先观察到标题消失，才会为新的标题布防；直接在旧标题持续显示时开始不会立即收杆。

## 核心流程

```text
Minecraft Title ROI 截图
  → 放大、灰度、对比度增强、锐化、二值化、反色、白色文字分离
  → 各版本独立中文 OCR / 多结果融合
  → 文字标准化、置信度与相似度匹配
  → 连续帧确认、状态验证、冷却去重
  → BITE_CONFIRMED → 立即右键收杆
  → WAITING_RESULT → latest.log 确认 SUCCESS / FAILURE / UNKNOWN
```

**latest.log 从不触发收杆。** 只有游戏画面的 Title “咬钩！”或“上钩！”可触发。鱼漂运动仅记录辅助置信度，不独立触发收杆。普通水面运动和旧版白色像素检测不会触发。

默认连续 2 帧、900 ms 确认窗口、1200 ms 候选超时、2000 ms 冷却。接受“咬钩”和“上钩”的有无感叹号、全半角和空白变体；清理多余符号，拒绝“未咬钩”“没上钩”等否定文本。OCR 默认相似度 0.80、置信度 0.65，均可在界面调整。提高阈值或帧数可降低误判，但会增加漏检或响应时间，应先通过真实游戏标题测试。

OCR 直接识别已框选的单行 Title，七种预处理版本分别识别后融合，不再对每个版本重复进行场景文字定位。白色文字分离抑制彩色背景和黑色阴影，去除小噪点；原始 ROI 仅用于预览，不直接提交 OCR。本机真实回归样本单帧约 170–200 ms，合成标题约 230–240 ms；真实耗时以界面显示为准。

“OCR 调试”页同时显示原始 ROI、放大图、最佳预处理结果、原始文字、标准化文字、目标、OCR 置信度、相似度、检测状态及七种版本的识别结果。“导入截图测试”在后台模拟连续帧确认，不操作鼠标；已裁剪 Title 图直接导入，完整游戏截图可勾选使用已保存 ROI。软件界面截图中的预览图应先裁剪，不能套用游戏窗口的 ROI 比例。“保存调试样本”导出图像和识别 JSON。

状态为 `IDLE / CASTING / WAITING_BITE / BITE_CANDIDATE / BITE_CONFIRMED / REELING / WAITING_RESULT / SUCCESS / FAILURE / UNKNOWN`。同一次标题动画只能触发一次，下一轮需要标题消失后重新布防。

## 日志结果与报警

| 日志内容 | 结果 |
| --- | --- |
| `[CHAT] 上钩! 您钓到了 [...]` | SUCCESS，解析鱼获，随机等待后重新抛竿 |
| `不行! 这个钓点已经枯竭，换一个地方吧。` | SPOT_DEPLETED，停止钓鱼并持续报警 |
| `不行! 您只能在有鱼群活动的钓点钓鱼。` | NO_FISH_ACTIVITY，停止钓鱼并持续报警 |
| 超过结果等待时间，默认 6000 ms | UNKNOWN，显示“未确认鱼获”，默认停止钓鱼 |

首次连接或手动重连日志会跳过已有内容；日志轮转后继续监听新文件。事件用文件世代、字节位置和原始行 hash 去重，新的相同错误行仍能再次报警。收杆前的日志位置及收杆时间用于匹配本轮结果。日志文件发生切换或结果无法可靠归属时，保守处理为未确认。

日志可感知服务器实际写入的鱼获、钓点错误和部分连接异常，不能完整反映游戏内所有事件。`game_log.extra_errors` 可配置额外严重错误短语，例如 `{"SERVER_ERROR": "服务器钓鱼暂时不可用"}`。

独立 `AlertManager` 后台线程管理 `NORMAL / WARNING / ALERT_ACTIVE / ACKNOWLEDGED`。发生严重错误时，后台窗口通过原生 `FlashWindowEx` 持续闪烁任务栏，前台窗口保持异常提示；`winsound` 默认每 3 秒重复声音。不会抢占 Minecraft 焦点。

点击“停止报警”停止声音和任务栏闪烁，异常仍保留在界面及历史记录中。新的错误可再次激活报警。退出程序释放报警资源。频率、时长、重复间隔、总报警开关和声音开关均可配置。关闭报警时仍保存错误并停止钓鱼。

## 界面与快捷键

实时页显示 Title 截图、OCR 证据、运行状态与结果确认率。历史页保留鱼获及错误事件，双击查看完整记录。结果确认率只表示日志确认比例，不代表经过实测的识别准确率。

| 快捷键 | 操作 |
| --- | --- |
| F6 | 开始 / 暂停 / 恢复 |
| F7 | 停止自动钓鱼，保留异常报警 |
| F8 | 框选 Title 区域 |
| F9 | Title OCR 测试，运行中再按一次停止测试 |
| F10 | 刷新当前 Title ROI 预览 |
| F11 | 框选鱼漂辅助区域 |

游戏失焦时暂停检测点击，回焦等待 3 秒恢复；结果等待超时仍按实际时间计算。ROI 选择和设置保存需先停止钓鱼。快捷键注册失败时可用界面按钮。

## 文件与验证

`config.json` 保存设置；`data/events.jsonl` 异步保存 BiteEvent、日志、异常和确认记录。BiteEvent 包括时间、Title 文字、OCR 置信度、ROI、鱼漂置信度、触发状态、收杆时间和结果。每次正常关闭软件会等待最后的记录写入磁盘，并自动保存 `data/events.snapshot.json`（累计上钩次数、成功/失败/未确认次数、最近鱼获、确认率和最近 500 条事件）。下次启动从完整事件文件恢复累计统计，同一次上钩的结果更新不会重复计数；界面只加载最近记录，完整鱼获历史仍保留在事件文件中。强制结束进程不会执行关闭快照，但已写入的事件仍可恢复。

主要模块：`title_detector.py`、`fishing.py`、`game_log.py`、`alert_manager.py`、`bobber_detector.py`、`gui.py`。截图、OCR、日志、报警、历史写入均不在 UI 主线程执行。

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tests/verify_ocr_ui.py
python -X utf8 tests/verify_native_alert.py
```

自动测试覆盖 Title 标准化、连续帧、冷却去重、错误日志、轮转、延迟旧结果、窗口 ROI 缩放、失焦点击限制、收杆与日志隔离、未确认超时及报警生命周期。OCR/UI 脚本同时使用合成中文标题和 `tests/fixtures/bite_title_real.png` 真实样本，验证“咬钩”标准化、候选、连续确认、去重及后台截图导入。真实样本裁自 2026-10-08 15:46:15 的软件截图内游戏预览，裁剪来源保存在同目录 JSON。`verification` 保存各预处理截图、融合结果、确认状态及原生窗口截图，不操作游戏。原生报警脚本会播放短声音，测试真实 Beep/FlashWindowEx 调用；前后台焦点分支通过注入验证，实际任务栏渲染和听觉效果需现场确认。

已验证提供截图中可见的真实“咬钩！”样本；尚未完成正在运行的游戏收杆与鱼获日志联调。首次使用应先测试 ROI 和实时标题，再观察鱼获确认；截图遮挡、字体差异和服务器消息格式变化都可能影响识别。
